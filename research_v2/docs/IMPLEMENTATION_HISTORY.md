# Numerical revisions and provenance

The dataset manifests and random seeds were frozen before performance runs. This was an interactive research run, not external preregistration. Revisions below were motivated by correctness or approximation diagnostics; original results remain archived.

1. **Polyhedral dual refinement.** Budget/filter/sample objectives initially relied on a less accurate primal path. Explicit feasible envelopes and dual bounds were added. The original development rows are in `results/pre_polyhedral_solver_refinement/`.
2. **G2 integration revision.** A fixed-grid ESS/scramble diagnostic exposed inadequate posterior quadrature. The planned fallback uses an observed-data-fitted proposal with 25% uniform support and explicit prior/proposal corrections. Original development, selection and G1 results are in `pre_importance_revision/`. Corrected development was rerun before freezing replacement candidates; all test seeds stayed fixed.
3. **G3 bootstrap initialization.** A resampled past window could contain an entirely unobserved asset column, causing a NaN diagonal initializer. Known-zero Gaussian EM now uses a past-only nominal initializer for such columns. The interrupted original G3 records remain in `pre_bootstrap_initialization_fix/`.
4. **Integer Top-k after filtering.** Filtering to 95% mass can leave an odd number of scenarios. Fractional CVaR at rho was corrected to equal-count Top-k with effective fraction ceil(rho*K)/K. Development and the affected methods were rerun on the same manifests. Candidate names happened to remain the same. Earlier results and selections remain in `pre_integer_filter_fix/`; they are not pooled in final summaries.
5. **Tolerance-based stopping.** The weighted-QP dual now stops once the originally required 1e-6u weak-duality gap is reached. It no longer needs to satisfy a stricter optimizer-internal stopping condition after the required decision tolerance is met.
6. **Direct Clarabel epigraph.** A separately checked native conic construction reduces modeling/optimization overhead for large polyhedral scenario problems. Its output is accepted only after the same QP-based bound check; the weighted-QP dual and CVXPY reference remain fallbacks. `native_conic_gate.json` includes a case needing fallback rather than concealing it.
7. **Precision escalation.** Scramble sensitivity triggered 4096-node audit references, a continuous-posterior MCMC check, and exact hidden-box corner maximization for the G2 B-Max audit. These diagnostics were not used to retune confirmed candidates. Their limitations enter the final interpretation.
8. **Evidence-budget support bounds.** An LP primal maximizer supplies a lower approximation to a support function, not an upper certificate. The final implementation repairs the LP dual to obtain a feasible upper bound. All 2,232 affected C-Budget rows were audited at their original holdings, with original bounds archived in `pre_budget_support_bound/`. True regret and holdings did not change. The corrected gaps are nonnegative and below the requested tolerance; this is a float64 numerical check, not interval arithmetic.
9. **Worst-group selector repair.** The original selector used the maximum of groupwise differences from MA. Requiring this to be negative imposed improvement in every group and made the positive-average-cost Blend trigger impossible. The intended criterion is the difference between the two methods' maximum group mean validation losses, with groups `(kind, family_id)`. The original frozen selection and confirmation remain intact. Both Blend methods were added to the same 24 development datasets; the repaired selector chose H-PostSampleK and C-LP-Max:0.01 for exploratory follow-up. `repair_screen` and `repair_confirmation` use the original data manifests and seeds. Because the original confirmation was already inspected, these supplementary comparisons are explicitly exploratory, not a fresh independent confirmation. Selection itself still uses only independent development future losses, never test truth.

Checkpointed method rows were preserved; an in-flight method was recomputed after process restart. Main comparisons use fixed manifest partitions, single-thread BLAS and shared-machine timings. Process wall time and CPU time are stored separately when available. Short interactive checks and the earliest exceptional interruption are not all in the runtime ledger, so it is not an exact accounting of the entire research session.

Each performance row has a source hash, but historical hashes alone are not complete historical source snapshots. The delivered source reproduces the final mathematical definitions and numerical tolerances; bit-for-bit reproduction of all superseded diagnostic versions is not claimed. The v1 repository files remain unchanged.

The native LaTeX compiler reported an environment error (`Unable to find standard directories for platform`). The editable source was retained and opened; the PDF was compiled using the already-installed TeX Live 2024 and visually checked. No TeX installation was added.
`ScenarioSet.prepare` now fingerprints Q, means, constraints, turnover and previous holdings before reusing scenario oracles. A mutation regression test passes. Main experiments constructed fresh scenarios or explicitly cleared turnover oracles, so this cache hardening does not alter their decisions. An initial import-scope error in the new test was corrected before the final Gate-V2 pass.
